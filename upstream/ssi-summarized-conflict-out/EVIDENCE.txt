EVIDENCE: a SERIALIZABLE transaction alone in its database fails with 40001 once SSI summarizes

Run 2026-11-10 on PostgreSQL 19rc1 (REL_19_RC1, 0b8bff042a), aarch64-darwin, Apple clang 21.0.0, meson, -Dcassert=true,
llvm disabled. The tree carries grizzle's two pin patches (scripts/pg/patches), which touch execGrouping.c, execMain.c,
nodeModifyTable.c, relcache.c, rel.h, relcache.h and a regression test; none touches predicate.c, heapam.c or the

   predicate.c, the rest of the path:

     1735-1745 no free sxact: SummarizeOldestCommittedSxact() (1432), SerialAdd (1464)

     3641-3647 a finished sxact is freed only once finishedBefore <= SxactGlobalXmin

   every new serializable transaction summarizes the oldest finished one.

4. WITH THE PATCH
   The same spec, with a counter added to the procedure: "summarized after 1400 transactions" in each permutation
   (the pool is (MaxBackends 136 + max_prepared_xacts 2) * 10 = 1380, probed every 100), and every transaction of both
   permutations commits; the server logs no error from the writer.
     src/test/isolation: All 135 tests passed (ok 135 - serializable-summarized-conflict-out).
     src/test/regress:   All 240 tests passed.
   Built with assertions, no warning in predicate.c. pgindent (src/tools/pgindent with the in-tree pg_bsd_indent)
   leaves predicate.c unchanged; git diff --check is clean. The patch applies with git apply --check, no fuzz, to
   stock 19rc1 and after grizzle's two pin patches.

5. SOUNDNESS
   XidIsConcurrent(xid) false means the xid finished before the transaction snapshot, so all its writes are in it and
   the reader has no rw-antidependency to it; every cancellation the patch skips rested on that edge. For such an xid
   the path without summarization already returns with nothing set (4068). Read adversarially by NEGATION on
   2026-11-10, which found no schedule the patched function commits that unbounded SSI would cancel: a LIVE invisible
   version's creator and a visible version's updater are never in the scan snapshot, which is the transaction
   snapshot or, for RI's PK-side checks, a later one (ri_triggers.c 1828, 2067, 2699), so they stay concurrent; a
   RECENTLY_DEAD invisible version's creator is non-concurrent only when the scan saw its delete; heapam passes
   SubTransGetTopmostTransaction and xip holds top-level xids; a prepared transaction is in xip while prepared.
