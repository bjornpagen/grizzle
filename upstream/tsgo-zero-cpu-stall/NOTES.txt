NOTES: tsgo-zero-cpu-stall

Status: NOT reproduced and NOT filed. Nothing has been sent anywhere. The owner files it by hand, and only once a stall has
left its goroutine dump (section 3) and reproduces on an unpatched compiler.

1. What this is.
   - grizzle's type-test batch (test/types/batch) runs the repository's TypeScript 7 compiler, tsgo, as one program over
     every type test's fixtures and generated programs.
   - Once, on a type error, that tsc sat at 0% CPU and never finished: no output, no exit, until the test's own timeout
     (an hour) ended the run.
   - There is no record of when it happened, which run it was, or which unit or type error was involved. Nothing in the
     repository, its TODO history or the session notes holds a ps listing, a sample or a dump of it.
   - A healthy tsgo check never goes without CPU progress for more than a fraction of a second (EVIDENCE.txt 2). So a
     check at 0% CPU is not a slow check. It is blocked: a deadlock among its goroutines, or a wait on something that
     never comes.

2. What grizzle does about it now (no upstream fix needed for grizzle to be safe).
   - test/types/batch/compiler.ts runs every tsgo check, the batch's and the scaling tests', under a stall guard. ps
     reads the check's process tree CPU time every second (stallSampleEvery). If that time does not move for 30 s
     (stallWindow, a measured Limit whose evidence is EVIDENCE.txt 2), the guard:
       - sends the compiler SIGQUIT, on which Go's runtime prints every goroutine's stack and exits;
       - fails the run with CompilerStalled, which carries that dump;
       - in the batch, has BatchStalled name the program and every unit it held, so each type test fails closed, never
         a hang.
   - test/types/batch/batch.test.ts holds the guard to that: tsgo's own watch mode, which idles at 0% CPU after its
     first check, must fail with CompilerStalled and a goroutine dump; a check run once, clean or with an error, must
     never be judged stalled.
   - So the next stall leaves exactly the evidence this report lacks: the goroutines' stacks at the moment of the
     stall.

3. When a stall happens again.
   - Take the CompilerStalled from the failing run. It names the batch's tsconfig and its units, and its message holds
     the whole goroutine dump.
   - Read the dump for the blocked goroutines: the main goroutine (normally sync.WaitGroup.Wait in the program's
     check), and each checker's state (chan receive, sync.Mutex.Lock, select). A healthy dump (EVIDENCE.txt 3) shows
     the checkers "running".
   - Reproduce on an unpatched compiler before filing:
       - grizzle's tsc is patched by `effect-tsgo patch` (pnpm install's prepare step). `tsc --version` prints
         "7.1.0-beta+effect-tsgo.0.67.1". The batch passes `plugins: []`, but the binary is still the patched one.
       - Recreate the batch's program: the units the failure names, the tsconfig it wrote (extends
         packages/devtools/tsconfig.base.json and tsconfig.base.json, noEmit, noErrorTruncation, customConditions
         grizzle-source).
       - Check it with an unpatched `npx -p typescript@next tsc -p <that tsconfig>`, and then shrink it toward one file.
         If only the patched binary stalls, the report goes to Effect's tsgo patch (github.com/Effect-TS/tsgo), not
         to TypeScript.
   - Then fill issue.txt's open sections and walk CHECKLIST.txt.

4. Where it goes.
   - TypeScript 7 is maintained in github.com/microsoft/TypeScript. github.com/microsoft/typescript-go was archived on
     2026-09-01 and takes no new issues; its old issues are still worth searching (CHECKLIST.txt A).
   - The typescript package's own package.json names https://github.com/microsoft/TypeScript/issues as its bug
     tracker.

5. Files.
   - NOTES.txt      this file.
   - CHECKLIST.txt  TypeScript's contribution policy, item by item, with what is still open.
   - EVIDENCE.txt   the healthy-run measurements, the sampler that took them, tsgo's answer to SIGQUIT, and the
                    environment.
   - issue.txt      the draft issue, its reproduction and dump sections open.
