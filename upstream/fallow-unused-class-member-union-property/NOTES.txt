NOTES: fallow-unused-class-member-union-property

Status: ready to file, NOT filed. Nothing has been sent anywhere. The owner files it by hand.

1. What this is.
   - fallow's unused-class-members check credits a member called through a property of a typed value only when the
     value's type is an interface or an object-literal type alias. A union of object types records no property types,
     so a call through it credits nothing (EVIDENCE.txt 3).
   - Narrowing plays no part. A union whose every arm declares the property at the same class is not credited either
     (repro.sh, Cell.viaUnionPropertyEveryArm).
   - fallow's opt-in type-aware mode credits every such call. The syntactic pass, the one `pnpm check` runs, does not.
   - Reproduced on fallow 3.38.1, grizzle's pin, and on 3.41.0, the latest release on 2026-11-07 (EVIDENCE.txt 1).

2. What grizzle does about it now.
   - check/params.ts ParamCell is a parameter's unification cell. Its uses widen or fix its type through use and
     useRelation, and the checker calls both on the cell of BindValue's "param" arm, a discriminated union, in
     check/checker.ts. fallow reports both as unused (EVIDENCE.txt 2).
   - ParamCell stays a class. Its type is mutable state that only a checked use may change, and the private #entry is
     what keeps any other writer out. The alternatives are each worse:
       - a record with a public mutable entry and free functions lets any module write the entry;
       - immutable cells with a table of entries make a cell without an entry representable, which then needs a
         failure path;
       - a record of closures is a class in disguise that only hides the members from fallow.
     BindValue stays a union, because the bound value is a param, a literal or a column. The code is right, and fallow
     is the part that has to change.
   - So .fallowrc.json keeps "use" and "useRelation" in usedClassMembers, with a pointer to this folder.
   - The cost of the entry: it is global by name, and a scoped rule needs an extends or implements clause, which
     ParamCell has neither of. Today no other class declares a use or useRelation member. A dead member named that on
     another class would go unreported (EVIDENCE.txt 4).
   - WriteParams.member is called on the params of a StatementPlaceholders, a union too
     (lower/conservative/context.ts). Its arms type params differently, an interface and a class, so it is credited
     only by a fix that credits every arm's type (issue.txt, "Suggested fix").

3. When a fallow release fixes it.
   - Run `sh repro.sh <path to the new fallow binary>`. The fix is in when the report lists Cell.never alone.
     Cell.never is the control: a run that reports nothing found no unused member at all, and it proves nothing.
   - Then delete "use" and "useRelation" from usedClassMembers, along with their sentence in the comment above it.
     Also delete "member" if `pnpm -s dead-code` stays clean without it. Delete this folder and its TODO.md line.

4. Where it goes.
   - github.com/fallow-rs/fallow, using its Bug Report issue template (.github/ISSUE_TEMPLATE/bug_report.yml).
   - CONTRIBUTING.md, "Reporting issues": a false positive includes the fallow output and a minimal reproduction.
   - CONTRIBUTING.md welcomes issues that an agent helped write, provided they are read before posting and keep the
     exact command and output.

5. Files.
   - NOTES.txt      this file.
   - CHECKLIST.txt  fallow's reporting policy, item by item.
   - EVIDENCE.txt   the reproduction's output on both versions, grizzle's own run, the cause in fallow's source, the
                    planted members, and the duplicate search.
   - issue.txt      the draft issue, under the bug template's headings.
   - repro.sh       writes the reproduction project to a temporary directory and runs a given fallow binary on it.
